# 기획 개요

장기고의 목표, 시장 분석, 차별화 전략, 기술 구성, 수익 모델, AI 방침, 로드맵이다. 2026-10-31에 작성한 기획 초안을 이후 결정 사항에 맞춰 정리했다. 세부 기획은 각 문서에서 정하고, 이 문서는 큰 방향만 담는다.

각 항목은 **확정**, **초안**, **미정**으로 표시한다.

## 목표 — 확정

- 앱 이름은 **장기고**(janggigo)다.
- 안드로이드, 아이폰, 웹에서 동작하는 한국장기 게임을 만든다.

## 시장과 경쟁 — 초안

### 1위 경쟁작: 카카오장기

| 강점 | 약점 (장기고의 공략 지점) |
|---|---|
| 깔끔한 UI, 기물 디자인, 애니메이션 | 한 판 끝날 때마다 강제 영상광고 |
| 놓아보기, 시간 연장, 복기 모드 | 비싼 스킨 아이템 |
| | 접장기(차 떼기, 포 떼기 등) 옵션 없음 → 방송 콘텐츠로 쓰기 어려움 |
| | AI 복기 기능 없음 |

위 분석은 기획 초안 작성 시점의 판단이며, 출시 전에 다시 확인한다.

### 정면 승부가 어려운 이유

- **동시 접속자 수:** 대전 게임은 사람이 많은 곳에 사람이 모인다. 바로 매칭되는 환경은 기능만으로 따라잡기 어렵다.
- **카카오 브랜드와 친구 목록:** 중장년층의 진입 경로를 이미 가지고 있다.
- **사용자층:** 40~60대 비중이 높아 익숙한 앱을 잘 바꾸지 않는다. 큰 글씨와 단순한 조작이 기본이다.

### 원칙

- 카카오장기의 UI와 그림을 베끼지 않는다. 장기 규칙은 누구나 쓸 수 있지만 디자인은 장기고 고유의 것으로 만든다.

## 차별화 전략 — 초안

틈새부터 공략한다.

| 공략 지점 | 내용 | 관련 문서 |
|---|---|---|
| 접장기 | 기물을 떼고 두는 대국. 방송인의 이벤트 대국과 콘텐츠용 | [game/handicap.md](./game/handicap.md) |
| 방송 친화 | 별도 방송인 모드 없이 비공개 방, 링크, 접장기, 관전으로 방송인이 시청자와 둔다 | [game/matching.md](./game/matching.md) |
| 광고 부담 감소 | 강제 영상광고 없이 보상형 광고만 넣는다 | |
| 웹 링크 대전 | 링크 하나로 설치 없이 바로 대국한다. 방송과 커뮤니티에서 퍼지기 좋다 | [game/matching.md](./game/matching.md) |
| 박보장기(묘수풀이) | 매일 문제를 내서 매일 들어올 이유를 만든다 | |
| AI 코치 | 형세 그래프, 실수 표시, 결정적 순간 분석. 하루 무료 횟수 + 보상형 광고 | 아래 AI 방침 |

**핵심 전략:** 방송인을 먼저 잡는다. "차 떼고 시청자랑 한판" 같은 콘텐츠가 곧 마케팅이고 유입 통로다. 사람이 적은 초기에는 AI 대국으로 매칭 공백을 메운다.

## 기술 구성 — 확정

| 구성 | 기술 |
|---|---|
| 앱 | Flutter (안드로이드, 아이폰, 웹). 웹은 Wasm 빌드 |
| 규칙 엔진 | `janggi_core` 순수 Dart 패키지. 앱과 대국 서버가 공유 |
| 로그인 | Firebase Auth. 구글, 애플, 이메일 (카카오는 출시 후 검토) |
| 진행 중 대국, 접속 상태, 관전 | Realtime Database (`asia-southeast1`, 싱가포르) |
| 유저 정보, 급수, 기보, 설정 | Firestore (`asia-northeast3`, 서울) |
| 대국 서버 (매칭, 수 검증, 서버 시계) | Cloud Run Dart (`server/game`, 서울) |
| 기타 서버 기능 (푸시 트리거, 채팅 검사, Admin) | Cloud Functions TypeScript (`server/functions`, 서울) |
| AI 대국, AI 복기 | Fairy-Stockfish를 Cloud Run 컨테이너에서만 실행 |
| 운영 | Admin 웹 (`server/admin`, React) |
| 결제, 광고 | 인앱결제(RevenueCat 권장), AdMob 보상형 광고 |

저장소 구성과 개발 규칙은 [dev_rules.md](./dev_rules.md)를 따른다.

### 기술 주의 사항

- **Flutter 웹 첫 로딩:** 엔진과 앱을 합쳐 수 MB라 첫 방문이 느리다. 로딩 화면과 캐싱으로 줄이고, 필요하면 초대 링크용 초경량 HTML 페이지를 따로 둔다.
- **Wasm 제약:** 지원하지 않는 브라우저는 자동으로 JS 빌드로 전환된다. 멀티스레드 렌더링에 필요한 COOP/COEP 헤더가 광고나 소셜 로그인 팝업과 충돌할 수 있어 테스트가 필요하다. 브라우저 지원 현황은 확정 전에 다시 확인한다.
- **Fairy-Stockfish 라이선스:** GPL-3라서 앱에 넣으면 앱 소스를 공개해야 할 수 있다. 서버 컨테이너에서만 실행하고, 출시 전에 라이선스를 직접 검토한다.
- **규모가 커질 때:** 동시 대국이 수천 판을 넘으면 실시간 부분만 자체 WebSocket 서버(서울)로 옮기는 것을 검토한다.
- **Firebase 환경:** 운영 프로젝트 하나로 출시하고, 개발과 테스트는 Emulator Suite로 한다. 출시 후 데이터 구조나 보안 규칙을 크게 바꾸기 전에 개발용 프로젝트를 만든다.

## AI 방침 — 초안

### 고민

방송인이 해설할 때 시청자가 "그냥 AI 돌려요"라고 해버리면 방송의 재미와 해설의 권위가 깎일 수 있다.

### 결론: 넣되, 사람을 돕는 도구로 설계한다

넣는 이유:

- 장기 AI(Fairy-Stockfish)는 이미 누구나 쓸 수 있다. 안 넣어도 "AI 돌려요" 댓글은 생긴다. 차이는 그 사용자를 앱 안에 붙잡느냐다.
- 체스에서 검증됐다. 엔진이 있어도 방송은 커졌고, 형세 막대 자체가 볼거리가 됐다.
- 카카오장기에 없는 차별점이고, 보상형 광고를 볼 가장 큰 이유가 된다.

설계 원칙:

- 대국이 끝난 뒤에만 쓸 수 있다. 진행 중인 대국에서는 금지한다(부정행위 차단).
- 결과는 보여주되 이유는 사람 몫이다. "결정적 순간 3곳", "실수/대실수" 정도만 표시한다.
- 이름은 "AI 코치"나 "AI 복기"로 한다. "AI 정답" 느낌은 피한다.
- 부정행위 탐지: AI 추천수와 너무 자주 일치하는 계정을 서버에서 걸러낸다.

### 사용 횟수 — 제안

- 구독이 없으므로 모든 사용자가 하루 무료 N판을 쓰고, 보상형 광고를 보면 1판씩 더 쓴다. 판 수는 서버 비용을 보고 정한다([monetization.md](./monetization.md)).

### AI 대국 — 미정

- AI 대국의 난이도 단계와 급수 반영 여부.
- AI가 서버에서만 돌기 때문에 AI 대국은 인터넷 연결이 필요하다. 로그인 없이 AI 대국을 허용하면 서버 비용과 남용을 어떻게 막을지 정해야 한다.

## 로드맵 — 초안

| 단계 | 내용 |
|---|---|
| 1단계 | `janggi_core` 규칙 엔진, 접장기, 대국과 복기 화면, 놓아보기. 대국 화면은 서버 없이 한 기기에서 양쪽을 두는 개발용 대국으로 확인한다(사용자 기능으로 내보내지 않음) |
| 2단계 | 온라인 대국(빠른 대국, 방, 링크, 신청), 급수, 로그인, 채팅과 신고, Admin 웹 |
| 3단계 | 스토어 출시, 결제와 광고. 세부는 [release.md](./release.md) |
| 4단계 | AI 대국과 AI 코치(하루 무료 횟수 + 보상형 광고). 사용자 반응을 보고 공개 범위를 조절한다 |

- 규칙 엔진과 기보 형식은 처음부터 AI 분석을 붙이기 쉽게 설계한다([game/notation.md](./game/notation.md)).
- 출시 시점과 단계 구분은 화면 기획 후 다시 정한다.
